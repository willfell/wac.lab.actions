# wacd Plan 3: `wac-ci` and `wac-cd` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship two reusable workflows in `wac.lab.actions`: `wac-ci` checks an app's pull requests and pushes nothing, and `wac-cd` versions, builds, publishes a per-app deploy chart, releases it through the gateway and proves it on a merge to `main`. Both are driven by one profile, `.github/wacd.json`.

**Architecture:** Every decision lives in a stdlib Python script under `scripts/` with a scenario test under `scripts/tests/`. The two workflows are thin YAML that check this repo out at `job.workflow_sha` and call those scripts. The gateway client is one script, `scripts/wacd-release.py`, that reuses `scripts/ci-release.py`'s transport by import and never modifies it, so the Plan 2 contract drops into one place.

**Tech Stack:** Python 3.12 stdlib (PyYAML only in tests and `check_actions.py`), bash, Helm 3.16.3 on runners (tests also pass on the local Helm 4), crane v0.20.6, kubeconform v0.7.0, GitHub Actions.

## Global Constraints

- No comments in any YAML or JSON file written or edited (fleet rule 1, user CLAUDE.md). Python and bash are commented normally.
- No emoji or glyph icons.
- Never use docker on the Mac. Never run kubectl, argocd, `helm push`, or anything that changes cluster state. Tests use temp dirs, local git repos and stub HTTP servers only.
- Push registry `registry.network.svc.cluster.local:5000` (plain HTTP); pull address `localhost:30500`. Never collapse them. Image `repository` in values is `localhost:30500/<name>`; digest matches `^sha256:[0-9a-f]{64}$`.
- Charts: `wac-app` is pulled from `oci://registry.network.svc.cluster.local:5000/charts/wac-app`; deploy charts are pushed to `oci://registry.network.svc.cluster.local:5000/deploy`, so chart `deploy/<app>` (what the registration names). A published deploy-chart version is never overwritten.
- Every reusable workflow declares `runner` (`type: string`, `default: ''`) and every job with steps has `runs-on: ${{ inputs.runner || vars.CI_RUNNER_SMALL }}` (Invariant 4). A job that calls a nested reusable workflow has no `runs-on` and passes `runner: ${{ inputs.runner }}`.
- Shared scripts are reached by `actions/checkout` of `willfell/wac.lab.actions` at `ref: ${{ job.workflow_sha }}`, `persist-credentials: false`, preceded by the `SHARED_WORKFLOW_SHA` regex step the existing gates use (Invariant 6).
- `uses:` of third-party actions are pinned to the same refs this repo already uses (`actions/checkout@v4`, `actions/setup-python@v5`, `actions/setup-node@v4`, `astral-sh/setup-uv@v5`); new ones (`actions/setup-go`) at an exact tag. Never `@main`/`@master`.
- No GitHub `environment:` on any job; the gateway rejects that claim.
- Existing components (`lab-gitops-deploy`, `lab-release`, everything else) and `scripts/ci-release.py` are not modified.
- Profile is `schema_version: 1`; unknown fields fail at every level.
- Version rules (spec): latest tag matching `<tag_prefix>X.Y.Z` reachable from HEAD; breaking is major, `feat` minor, anything else patch; no prior tag gives `0.1.0`. The version is the image tag, the chart version, the git tag suffix and the GitHub Release name.

## Rulings (choices the spec left open, each reported to wacd-init with its cost if wrong)

1. The values file may set `name` and `image` (the chart requires them and nothing else knows them); it must not set `app`, `images` or `global`. `wac-cd` writes `app` from the profile and `images` from the build. Cost if wrong: values files move one key; the packager's forbidden-key list changes.
2. Rollback uses a separate input, `rollback_version`, accepted only on `workflow_dispatch`; baton's caller-computed version is `version` with `version_source: caller`. The caller's `cd.yml` maps its own dispatch input `version` to `rollback_version`. Cost: an input rename in a minor.
3. A run whose HEAD already carries a `<prefix>X.Y.Z` tag is a resume: it skips build and publish and releases that version. A chart already published at the computed version with this run's source SHA is accepted and only the tag is pushed. Cost: none beyond a reviewer preferring a hard failure.
4. wac-ci runs `npm ci` itself before `ci.commands` for `stack: node`; nothing implicit for `go`. Cost: a profile that also lists `npm ci` installs twice.
5. Health check: served `sha` must equal the expected source SHA (rollback and resume expect the chart's recorded revision). The optional profile field `health_expect_db_ok` (boolean, default `true`) additionally requires `db == "ok"`; wac sets it `false` (its route returns only `{sha}`), as it passes `health_expect_db_ok: false` to `lab-gitops-deploy` today. (wacd-init, correcting the first draft.)
10. Publish-only (spec cutover step 1): `wac-cd` input `deploy` (boolean, default `true`). With `false`, a computed release becomes `mode=publish`: plan, build and publish (chart push and git tag) run; deploy and github-release are skipped; the run ends green. A resume with `deploy: false` is `mode=none` (already published). `rollback_version` with `deploy: false` fails. Cost: an input rename.
11. Render parity in CI (spec cutover step 1, "CI proves render parity with deploy/k8s"): `wac-ci` input `parity_kustomize_dir` (string, default `''`). When set, the render job also runs `kustomize build` on it and `scripts/wacd-parity.py` compares the two renders under Plan 1's normalization, ported from `wac.lab` `tests/wac_app/render.py` (branch `feat/wac-app-chart`), failing on any difference. Removed from the caller in cutover step 3. Cost: the port drifts from lab's normalize if lab changes it; the wacd plugin uses this same script locally, so there is one copy outside lab.
6. Deploy-chart provenance follows the Plan 2 contract: `Chart.yaml` `annotations` carry `org.opencontainers.image.revision: <source sha>` and `wacwini.com/images: <space-separated localhost:30500/<image>:<version>@sha256:<hex> refs>`, sorted by image name. `wac-cd` reads both back from the Helm config blob (the JSON Chart.yaml), as the gateway does. `appVersion` equals `version`. The chart name is the profile's `app`, which must equal the registered Application name. Cost: none expected; the contract fixes it.
7. Release readiness beyond the contract's proof: every Deployment image naming one of this release's repositories must be exactly its `localhost:30500/<name>:<version>@<digest>`, and at least one must. Cost: a cron-only image never appears in a Deployment, which this rule allows.
8. Nested gate calls in `wac-ci` use local paths (`./.github/workflows/actionlint.yml`), which GitHub resolves from the same commit as the calling reusable workflow. Cost if GitHub resolves them against the app repo instead: the first `wac-ci` run fails at start-up and a patch switches to fully qualified refs.
9. Fleet rule 3 keeps the bootstrap clause (wacd-init overturned the first draft): exactly `3. A deploy is a merge to `main` reconciled by Argo CD, or a `wac-cd` release through the gateway; never a change to cluster state by hand, outside the bootstrap exceptions lab documents.`

## The gateway contract (Plan 2, fixed)

Source: `wac.lab` branch `feat/wacd-registrations` commit `01f212ad`, `docs/ci-deploy-contract.md`, section "Chart releases (wac-cd)". Isolated in `scripts/wacd-release.py` as `RELEASE_BODY`, `STATUS_BODY` and `ready()`. Same URL, audience, CA file, OIDC flow and transport as `ci-release.py`; a fresh token per request.

- Identity: caller `.github/workflows/cd.yml` on `refs/heads/main`, event `push` or `workflow_dispatch`, `job_workflow_ref` exactly `willfell/wac.lab.actions/.github/workflows/wac-cd.yml@refs/tags/vX.Y.Z`, no `environment`. So the gateway call must be a job defined in `wac-cd.yml` itself, and the caller file must be named `cd.yml`.
- `release`: request exactly `{"operation": "release", "version": "X.Y.Z"}` (`^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$`). 200: the status object plus `released: {version, chart_digest, chart_source_sha, previous_version, sync_requested}`. Repeating it is idempotent.
- `status`: request exactly `{"operation": "status"}`. 200: `{application, chart, version, chart_digest, automated, source_sha, sync: {status, revision}, health: {status}, operation_phase, deployments: [{name, generation, replicas, status, images}]}`. `sync.revision` is the chart manifest digest, not the version.
- Proved when one status shows `version == V`, `sync.status == "Synced"`, `sync.revision == released.chart_digest`, `health.status == "Healthy"`, `automated is True`, and each Deployment has `status.observedGeneration >= generation` and `updatedReplicas`, `readyReplicas`, `availableReplicas` equal to `replicas` (no `unavailableReplicas`), plus Ruling 7.
- Errors: 400, 403, 404 fail at once; 503 retries with a fresh token until the deadline. Nothing else is retried.
- Deploy chart: registry repo `deploy/<app>`, tag `<version>`, Helm config media type, wac-app vendored, annotations per Ruling 6. The gateway requires on a push that the revision equals the token SHA; on dispatch, any ancestor of `main`.

## Review Focus

1. A re-run after the deploy chart was pushed but the git tag push failed: the chart is found with this run's revision, the push is skipped and the tag is pushed; with another revision it fails naming both SHAs. (Task 3, Task 7)
2. A computed version whose tag already exists on another commit: the plan step fails naming the tag and that commit. (Task 2)
3. Tags of other families or non-release shapes (`ui-v1.2.3`, `app-v1.0.0` under prefix `v`, `v1.2`, `v1.2.3-rc.1`, `1.2.3` under prefix `v`) are ignored when finding the latest tag. (Task 2)
4. A values file that sets `app`, `images` or `global`, or is not a mapping: packaging fails naming the key. (Task 3)
5. A rollback to a version that is not in the registry, or `rollback_version` on a push: the plan fails before any gateway call. (Task 3, Task 7)

The schema, every field required unless marked optional, unknown keys rejected at every level:

| Field | Rule |
| --- | --- |
| `schema_version` | integer `1` exactly (`True` is not `1`) |
| `app` | `^[a-z][a-z0-9-]{0,39}$` |
| `chart_version` | `^\d+\.\d+\.\d+$` |
| `values_file` | relative path, no `..` segment, no leading `/`; the file must exist relative to the profile's repo root (the parent of `.github/`) |
| `tag_prefix` | `^([a-z][a-z0-9-]*)?$` (may be empty) |
| `health_url` | `^http://[a-z0-9]([a-z0-9.-]*[a-z0-9])?\.svc\.cluster\.local(:[0-9]{1,5})?/\S*$` |
| `health_expect_db_ok` | optional, a JSON boolean (not `"false"`, not `0`); default `true` |
| `images` | non-empty list; each `{name, dockerfile, context, sha_build_arg?}`; `name` `^[a-z0-9][a-z0-9._-]{0,63}$` and unique; `dockerfile`, `context` relative paths as above; `sha_build_arg` optional `^[A-Z_][A-Z0-9_]*$` |
| `ci` | `{stack, node_version?, go_version?, commands}`; `stack` `node` or `go`; `node_version` required for and only allowed with `node`, `^\d+(\.\d+){0,2}$`; `go_version` the same for `go`; `commands` non-empty list of non-empty strings without newlines |

### Task 2: Version computation

**Files:**
- Create: `scripts/wacd-version.py`
- Test: `scripts/tests/wacd-version.test.py`

**Interfaces:**
- Produces: `bump(latest: str | None, messages: list[str]) -> str`; `latest_tag(tags: list[str], prefix: str) -> str | None` (returns the bare `X.Y.Z` of the highest tag fully matching `re.escape(prefix) + r"(\d+)\.(\d+)\.(\d+)"`, numeric ordering); `plan(repo: Path, prefix: str, source: str, caller_version: str | None) -> dict` returning `{"mode": "release"|"resume"|"none", "version": str, "tag": str}`; raises `VersionError`.
- Produces CLI: `python3 scripts/wacd-version.py --prefix P [--version-source commits|caller] [--version V] [--deploy true|false]` run inside the app checkout (full history, tags fetched); prints `mode=`, `version=`, `tag=` lines. Source SHA is `git rev-parse HEAD`.

Rules for `plan`:
- If HEAD carries a tag fully matching the prefix pattern: `mode=resume` with that version (highest if several), whatever the commits say.
- `commits`: latest is `latest_tag` over `git tag --merged HEAD`; messages are the full bodies of `git log <prefix><latest>..HEAD` (all of HEAD's history when there is no tag); version is `bump(...)`.
- `caller`: empty `--version` gives `mode=none`, `version=`, `tag=`; otherwise it must match `^\d+\.\d+\.\d+$`.
- Then if tag `<prefix><version>` exists and points at another commit: `VersionError` containing the tag and that commit's SHA.
- `--deploy false` (Ruling 10) maps the result last: `release` becomes `publish`, `resume` becomes `none` (version and tag kept in the output), `none` stays `none`. `plan()` takes `deploy: bool = True`.
- `bump`: `None` → `0.1.0`. A message is breaking if its first line matches `^\w+(\([^)]*\))?!:` or any line starts `BREAKING CHANGE:` or `BREAKING-CHANGE:`; feat if its first line matches `^feat(\([^)]*\))?:`. Breaking anywhere → major (`X+1.0.0`), else feat anywhere → minor, else patch, including when there are no commits.

### Task 3: Registry state and deploy-chart packaging

**Files:**

- Test: `scripts/tests/wacd-chart.test.py`

  - `python3 scripts/wacd-chart.py chart-images --registry R --app A --version V` prints `images=<json>`; exit 1 when absent.

  - `python3 scripts/wacd-chart.py ci-images --profile P` prints the JSON images map wac-ci renders with: each image `{"repository": "localhost:30500/<name>", "tag": "ci"}`.
