# wacd Plan 5: the `wacd` plugin and the four rewritten skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a `wacd` plugin in `wac.plugins` with `wacd:onboard` and `wacd:release`, plus a render-parity tool. Rewrite `deploy-verify`, `lab-onboard-app`, `suite-add-app` and `fleet-ci-routing` so each one describes both deploy routes while the fleet is mixed.

**Architecture:** `plugins/wacd/` is a local tier-3 (`team`) plugin. One Python CLI, `skills/onboard/onboard.py`, does the deterministic work: `discover` reads an app checkout, `render` runs `helm template` of `wac-app` against the app's values, `kustomize` runs `kustomize build`, and `parity` runs both and hands them to Plan 3's `wac.lab.actions` `scripts/wacd-parity.py`, the same comparison `wac-ci` runs, from a checkout at the pinned tag. The plugin keeps no copy of the normalization. The CLI uses inline PEP 723 metadata and runs with `uv run`. Its unittest suite runs from `plugins/wacd/scripts/selftest.sh`, which `scripts/validate-plugins.py` already runs for every plugin. The skills are prose, written test-first with subagent pressure scenarios (superpowers:writing-skills). Every field name, input and command a skill takes from Plans 2 and 3 sits in one `## Interfaces` table per skill, so filling them in is a one-table edit.

**Tech Stack:** Python 3 with PyYAML 6.0.2 via `uv`, Helm 4 (local) for `helm template`, kustomize 5, `gh`, Claude Code plugin conventions, the repo's own `scripts/validate-plugins.py` and `scripts/release.py`.

- No emoji or glyph icons anywhere (fleet rule 2).
- No `version` in any `plugin.json` or in the marketplace (Invariant 1).

- Produces, CLI `uv run <skill directory>/onboard.py <command>`. Human messages go to stderr, results to stdout. Exit 0 means done or parity, 1 means parity failed, 2 means a usage or tool error, and every error line ends with `Fix: ...`.
  - `discover <checkout>` prints JSON `{"route": "wacd"|"cutover"|"legacy"|"none", "profile": <path or null>, "kustomize_dirs": [<dir>], "deploy_steps": [{"workflow": <path>, "job": <id>, "uses": <action ref>, "with": {...}}], "dockerfiles": [<path>], "tags": {<prefix>: <latest X.Y.Z>}}`.
    - A deploy step is any step whose `uses` contains `/lab-gitops-deploy@` or `/lab-release@`.
    - `route` is `wacd` with a profile and no deploy step, `cutover` with both, `legacy` with a deploy step and no profile, and `none` with neither.
    - `kustomize_dirs` lists every tracked directory with a `kustomization.yaml`.
    - `tags` groups `git tag` output matching `^(.*?)(\d+)\.(\d+)\.(\d+)$` by prefix, keeping the highest by integer tuple.
  - `render --chart <wac-app dir> --values <file> --profile <wacd.json> --namespace <ns> [--out <file>]` writes the output of `helm template app <chart> --namespace <ns> -f <values> -f <injected>`.
  - `kustomize <dir> [--out <file>]` writes the output of `kustomize build <dir>`.
  - `parity --checkout <app repo> --chart <wac-app dir> --actions <wac.lab.actions checkout> --namespace <ns> [--kustomize-dir <dir>]`:
    1. renders with the profile's `values_file`;
    2. builds the one discovered kustomize dir (exit 2 naming them all when there are several, with `Fix: pass --kustomize-dir`);
    3. writes both outputs to a temp dir and runs `uv run --no-project --with pyyaml==6.0.2 python3 <actions>/scripts/wacd-parity.py <kustomize.yaml> <helm.yaml>`, streaming its output.

    It exits 0 only when that exits 0 and printed a line starting `parity:`. A missing `<actions>/scripts/wacd-parity.py` is exit 2, with `Fix: check out wac.lab.actions at the tag the app pins (v1.24.0 or later)`.
- Produces, Python API in `onboard.py`, for tests: `injected_values(profile: dict) -> dict`, `discover(checkout: Path) -> dict`, `parity(checkout, chart, actions, namespace, kustomize_dir=None) -> int`, `class ToolError(Exception)`.
- `injected_values(profile)` returns `{"app": profile["app"], "images": {i["name"]: {"repository": f"localhost:30500/{i['name']}", "tag": "parity"} for i in profile["images"]}}`, mirroring what Plan 3's `wac-cd` writes.
